# BEL CANTO · 美声效果器

浏览器里的实时人声效果器，支持麦克风输入和音频文件。
处理链包含变调、共振峰、颤音、饱和、压缩、合唱和混响。
旋钮实时调参，文件和录音均可导出为 WAV。

## 界面语言

界面使用英文。动态提示集中在 `src/strings.js`，静态文案、参数与面板标签位于 HTML 和对应模块中。

## 快速开始

需要 Node.js 22.13.0 或更新的 22.x 版本，或 Node.js 24 及更新版本。

```bash
npm start
```

打开 <http://127.0.0.1:5188>。页面需要 HTTP 服务，`file://` 不支持 AudioWorklet。
麦克风需要浏览器授权，使用耳机可避免啸叫。

顶部的监听开关只改变扬声器输出，增益过渡的时间常数为 0.02 秒。
它不影响处理链、IN/OUT 电平表、录音和文件导出，切换音源后保持原状态。

## 模式与启动是两步

顶栏的 **麦克风 / 音频文件** 只切换模式，不启动，也不弹任何权限框或文件框：

- 点 **麦克风** 只进入麦克风模式：不请求权限、不建立音频链、不出现麦克风授权弹窗，
  连 `AudioContext` 都不会创建。传输行随后出现 **开启麦克风**，点了才请求权限、
  建立输入节点并开始实时演唱；运行中同一个按钮变 **关闭麦克风**，关闭后回到
  「已进入但未开启」，可以再次开启。
- 点 **音频文件** 只进入一个空的文件模式：不弹系统文件框，传输行出现 **选择文件**，
  点了才弹。未载入文件时 ▶ / LOOP / 时间轴 / 导出全部灰掉且不可点；载入后这些控件才恢复，
  并且仍然**只载入、不自动播放**。拖放文件/整窗拖入仍会直接载入并进入文件模式。

首屏启动遮罩里的按钮同样只负责进入模式（「进入麦克风模式」/「进入文件模式」），
不会直接开麦或弹文件框。状态模型是 `state.mode = 'none' | 'mic' | 'file'` 加
`state.micOn`，所有 DOM/aria 由 `renderModeUI()` 统一同步；`AudioContext` 和音频链
只在真正启动（开启麦克风或解码文件）时才创建，进入模式本身不碰音频硬件。

模式切换会做清理：麦克风运行中切到文件模式会关闭麦克风，未保存录音按既有规则
自动丢弃并提示；文件播放中切到麦克风模式会停止播放，但**已载入的文件和播放位置保留**，
切回文件模式时仍停在原位置，不会自动续播。状态栏区分四种状态：麦克风未开启 /
麦克风实时 / 文件已载入未播放 / 文件播放中。

## 两种用法

- **麦克风**：进入麦克风模式后，点 Start mic 并授权即可实时演唱。STFT 延迟为 2048 个采样，具体时长随采样率变化。
- **音频文件**：拖入窗口，或进入文件模式后点「选择文件」
  （WAV / MP3 / M4A-AAC / FLAC / OGG / AIFF…）→
  **只载入、不自动播放**，播放头停在 0、按钮显示 ▶，点一下才开始。
  传输行里有一条暗金波形时间轴：**点击任意位置跳转，按住拖动连续定位**；拖动时浮出时间气泡，
  松手后原来在播放就从新位置接着播，原来暂停就停在那里等 ▶。
  右侧 **LOOP** 是独立的循环开关，**默认关闭**：关闭时播到末尾自动停止并回到开头，
  开启时播到末尾自动回绕继续；开关状态在切换文件时保留。时间显示为 `当前时间 / 总时长`。
  麦克风模式没有可定位的源，时间轴整条隐藏。
  调好后点「Export WAV」，会用 `OfflineAudioContext` 以同样的处理链离线渲染，
  **始终导出整段文件，与当前播放头位置、循环开关状态无关**，并保留 3 秒混响尾音。
  导出与监听走**同一条处理链、同一组参数**：实时链路和离线渲染各自建图，但节点类型、
  参数映射、混响 IR 的随机种子一致。导出使用当前 AudioContext 的采样率，输出双声道 PCM16 WAV。
  重复导出的误差由导出测试检查，阈值见下文。

麦克风模式下还有「录制」按钮：录制中可随时点「暂停」，此时 `MediaRecorder` 冻结采集与计时，
电平表/波形仍在动（那只是监听信号）；点「继续」从暂停点接着录，**写进同一个 blob、同一条 take**，
不会拆成两条下载。暂停中仍可「停止」，停止后**不会自动下载**，本次录音先停在待定状态，
界面上出现 **Save WAV / Discard** 两个按钮和冻结的总时长。这个时长只算实际录制时间，不含暂停。
点「保存 WAV」才导出 `belcanto-take-<时间戳>.wav`：解码 opus/webm 时进度条显示「解码中…」的
不确定态，编码 16bit PCM 时按写入的采样块回报进度；进度到 100% 后下载、
提示并回到 idle，解码/编码失败则显示可见的「保存失败」并保留本次录音，可以重试。
暂停中或待定时切换麦克风/文件音源、关闭页面，会丢弃未保存的录音。

浏览器无法解码 ALAC、AIFF 或 CAF 时，页面会请求本地 `/api/convert` 服务，
通过 macOS 的 `afconvert` 转成 WAV 再载入。这需要使用 `npm start` 提供的本地服务。

## 界面

| 区域               | 参数                              | 说明                                                                         |
| ------------------ | --------------------------------- | ---------------------------------------------------------------------------- |
| **VOICE 声部**     | PITCH / FORMANT / VIBRATO / DEPTH | 移调 ±12 半音；共振峰 ±12 半音（独立于音高）；颤音速率 3–8Hz、深度 0–80 音分 |
|                    | PRESERVE 保持共振峰               | 开：升调时声道不变（自然）；关：共振峰跟着音高走，音色变尖细                 |
| **RESONANCE 共鸣** | WARMTH / RING / SMOOTH / AIR      | 胸腔厚度 / 2.9kHz 歌手共振峰 / 去 5.6kHz 锐利感 / 空气感                     |
| **CHARACTER 动态** | DRIVE / COMP / INPUT / OUTPUT     | 电子管式饱和 / 压缩 / 输入输出增益                                           |
| **SPACE 空间**     | SIZE / REVERB / CHORUS / WIDTH    | 空间大小 / 混响量 / 合唱感 / 立体声宽                                        |

操作：拖动旋钮（向上增大）、`Shift` 精调、双击复位、滚轮微调、方向键可访问。
拖动时旋钮上方会浮出数值气泡。

右上角的 **A / B** 是两组参数快照（快捷键 `A` / `B`），可以把两版调法放在一起对比：
调好 A，切到 B 再改一版，来回按 A / B 直接听差别。

右侧显示屏显示音名、频率和范围为 ±50 音分的音准表，偏差在 ±8 音分内显示绿色。

显示屏右上角的 **SPLIT / SPECTRUM / WAVE** 可以切换监看方式：SPLIT 是"频谱 + 波形"上下分屏，
SPECTRUM 是全屏频谱（看得清泛音结构），WAVE 是全屏示波器（看得清波形和动态）。选择会被记住。

预设：Tenor、Soprano、Lyric Baritone、Choir Hall、Cathedral、Studio。

预设栏右侧的 **↺ RESET** 一键把 16 个旋钮恢复 `src/ui/params.js` 里的出厂默认值（`def`），
`PRESERVE` 回到开，下拉切到 **Custom**。它更新当前 A/B 槽，保留另一槽，不重置播放或录音状态。
RESET 和预设切换对连续参数使用时间常数为 0.2 秒的平滑，PRESERVE 立即切换；手动旋钮和 A/B 切换保留即时更新路径。

## 信号链

```
输入 ─ TRIM ─ 变调/共振峰(AudioWorklet) ─ 高通78Hz ─ 暖度 ─ 2.9k共振峰 ─
去锐利 ─ 空气感 ─ 饱和(WaveShaper 4x) ─ 压缩+限幅(Worklet) ─ 颤音(调制延迟) ─
        ├─ 干声 ────────────────────────────────┐
        ├─ 合唱 L/R (两路不同速率的调制延迟) ────┤─ 总线 ─ 输出 ─ 监听开关 ─ 目的地
        └─ 混响 (预延迟 + 程序化生成的 IR) ──────┘
```

## 技术要点

**变调与共振峰解耦**（`src/dsp/pitch-formant.js`）

固定 hop 的 STFT 频谱重映射：

- 每一帧 FFT，得到幅度 `|X[k]|`、相位 `φ[k]` 和瞬时频率 `ω[k]`
- 输出第 `k` 个 bin 取输入第 `k/p` 个 bin 的幅度（`p = 2^(半音/12)`）
- 合成相位按 `ω[k] × p × hop` 推进，保证重叠相加时相邻帧相干
- 共振峰：倒谱平滑估计谱包络，把包络整体缩放 `g = F/p`，音高不变、只移动"共鸣腔"
- IFFT + Hann 窗重叠相加，按 `Σw²` 归一化

固定 hop 的频域重映射避免了时间拉伸与重采样导致的帧内包络位移。
`p = 1` 时的透明性由 DSP 测试检查，波形相关度阈值为 0.99995。

降低共振峰会使频谱包络向低频移动。关闭 `PRESERVE` 后，共振峰随音高移调。

**动态处理**

`src/worklet/dynamics-processor.js` 实现压缩和软削波限幅，直接控制包络与增益计算。
实时处理和离线导出使用相同实现，不依赖内置压缩节点的自动补偿增益。

**混响**

`src/audio/reverb.js` 程序化生成脉冲响应：指数衰减噪声 + 随时间变暗的低通 +
稀疏早期反射，按峰值归一化。不依赖任何音频素材。

## 检查与测试

安装开发依赖后检查格式、代码和发布文件清单。页面运行不加载这些开发依赖。

```bash
npm ci
npm run format:check
npm run lint
npm run test:tools
npm run check:release
```

DSP 测试不需要浏览器或本地服务：

```bash
npm test
```

测试要求透明性波形相关度不低于 0.99995、移调误差小于 12 音分，并检查共振峰解耦和极端参数稳定性。
`npm test` 只运行 DSP 测试，浏览器测试需单独运行。

浏览器测试使用 Chrome DevTools Protocol。通过 `CHROME` 指定支持 `--headless=new` 的 Chromium 可执行文件。
先另开终端运行 `npm start`，默认地址为 `http://127.0.0.1:5188`。
修改服务端口时使用 `PORT`，并将测试的 `BASE_URL` 改为相同地址。
工具为浏览器自动分配 CDP 端口，也可通过 `CDP_PORT` 指定端口。

浏览器测试使用 `tools/test-vocal.wav` 作为合成输入，可用生成脚本重新生成：

```bash
node tools/make-test-wav.mjs
```

随后运行：

```bash
node tools/cdp-run.mjs http://127.0.0.1:5188/tools/e2e.html '^E2E_PASS$'
node tools/ui-test.mjs
node tools/rec-test.mjs
node tools/file-test.mjs
node tools/export-test.mjs
```

| 测试          | 覆盖                                                                      |
| ------------- | ------------------------------------------------------------------------- |
| `ui-test`     | 英文界面、16 个旋钮、预设、A/B、RESET、视图、模式进入与显式启动、参数平滑 |
| `rec-test`    | 录制、暂停、待保存状态、保存进度、失败重试、丢弃及音源切换                |
| `file-test`   | 载入不自动播放、循环、定位、切换音源及整段导出                            |
| `export-test` | WAV 格式、采样率、源时长加 3 秒尾音、导出进度、重复导出及监听隔离         |

文件和导出测试要求 WAV 采样率等于当前 `AudioContext`，时长为源文件加 3 秒，容差为 0.15 秒。
重复导出的采样差异最多为 1 LSB，不同采样点占比不超过 0.02%。
录音测试要求暂停不计时、停止不下载、保存失败保留录音，监听静音不影响录音内容。
这些是测试断言，运行结果以对应命令输出为准。

`DOWNLOAD_DIR` 指定下载产物的父目录，工具在其下创建本次运行的独占目录，保留下载产物并打印实际路径。
浏览器 profile 和第二输入的临时目录由工具创建并清理，不清空下载父目录。

## 已知限制

- 变调基于 STFT 重映射，大幅移调（>7 半音）时会有轻微的"相位感"，人声 + 混响下不明显。
- STFT 引入 2048 个采样的延迟，具体时长随采样率变化，不适合与未补偿延迟的干声直接叠加。
- 混响 IR 在调整 SIZE 时会重建（约 140ms 防抖），期间可能有一丝咔哒声。
- 导出沿用当前 AudioContext 的采样率；如果系统音频设备是 44.1kHz 而文件是 48kHz，
  监听与导出之间会有一次设备重采样的极细微差别。
- 麦克风与外放同时使用可能啸叫。监听开关可关闭扬声器输出，处理、录音与导出仍继续。
